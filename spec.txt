0. Coding and Schema Conventions (Mandatory)
This section defines strict conventions that MUST be followed by any implementation, whether manual or AI-generated.
0.1 Database Naming Conventions
All database tables and columns MUST follow a strict prefix-based naming convention.
Table Naming
   * All tables MUST use a 3-letter prefix indicating the logical entity group

   * Prefix MUST be included in the table name

   * Table names MUST be singular and upper-case with underscores

Examples:
      * BAJ_BATCH_JOB

      * TBJ_TENANT_JOB

      * BSC_BATCH_SCHEDULE

      * BRQ_BATCH_RUN_REQUEST

      * BIN_BATCH_JOB_INSTANCE

Column Naming
         * Every column MUST include the same prefix as the table

         * No column may be declared without a prefix

         * Primary keys MUST follow pattern: <PREFIX>_ID

         * Foreign keys MUST follow pattern: <PREFIX>_<RELATED_PREFIX>_ID

Example (BAJ_BATCH_JOB):
            * BAJ_ID

            * BAJ_JOBNAME

            * BAJ_TIMEOUT_SEC

Example (BIN_BATCH_JOB_INSTANCE):
               * BIN_ID

               * BIN_BRQ_ID

               * BIN_TEN_ID

               * BIN_BAJ_ID

               * BIN_STATUS

No generic column names like Id, Name, Status are allowed.
0.2 Field Documentation Requirement
Every database field MUST be documented with:
                  * field name

                  * data type

                  * nullable or not

                  * valid values, if enum

                  * description

This documentation MUST exist in:
                     * the technical design document

                     * XML documentation in entity classes where applicable

                     * EF Core configuration comments where applicable

No undocumented fields are allowed.
0.3 Class and File Structure Rules
All C# types MUST follow these rules:
                        * one public class per file

                        * file name MUST match the class name exactly

                        * enums MUST be in separate files

                        * interfaces MUST be in separate files

                        * entity configurations (IEntityTypeConfiguration<T>) MUST be in separate files

                        * background services (SchedulerService, RequestFiringService, EvaluatorService, DispatcherService) MUST each be separate classes in separate files

0.4 EF Core Configuration Rules
                           * Fluent API MUST be used for all entity configuration

                           * Data annotations MUST NOT be used for schema definition

                           * All indexes MUST be explicitly configured

                           * All unique constraints MUST be explicitly configured

                           * Filtered indexes, where required, MUST be explicitly defined

                           * Enum-to-string conversion MUST be explicitly configured

                           * Max lengths MUST be explicitly configured

                           * Required vs optional properties MUST be explicitly configured

0.5 Enum Handling
Storage Rule
All enums MUST be stored as strings in the database.
API Rule
All enums MUST be exposed as strings in API JSON.
Implementation Rule
                              * EF Core MUST explicitly map enums to strings

                              * Database columns storing enums MUST be nvarchar(...)

                              * Valid string values MUST be documented in this specification

                              * API request/response DTOs MUST serialize enums as strings

Numeric enum persistence is not allowed in v1.
Numeric enum JSON values are not allowed in v1.
Forward Compatibility Rule
Enum string values are part of the persisted contract and MUST be treated as stable.
Renaming an enum member is a breaking persistence change and MUST NOT be done without an explicit migration strategy.
0.6 General Implementation Principle
Where a future version could support multiple strategies, v1 MUST choose exactly one behavior and implement it consistently.
No implementation-defined runtime behavior is allowed for:
                                 * enum values

                                 * state transitions

                                 * retry behavior

                                 * cancellation behavior

                                 * dependency matching

                                 * scope matching

                                 * misfire handling

                                 * concurrency counting

                                 * manual request expansion

                                 * blocked-instance reevaluation

                                 * force semantics

                                 * process launch planning

                                 * placeholder resolution

If a behavior is not explicitly defined as supported in v1, it is not supported in v1.
0.7 ScopeKey Semantics
ScopeKey is a first-class orchestration concept.
Purpose
ScopeKey exists to allow the same job to run multiple times for the same tenant for different logical scopes, for example:
                                    * same tenant, different subtenant

                                    * same tenant, different portfolio

                                    * same tenant, different business area

Canonical Rules
                                       * ScopeKey is always persisted as a non-null string

                                       * Tenant-wide/default scope MUST be stored as empty string ''

                                       * null is not allowed for persisted scope values

                                       * Scope matching is case-sensitive

                                       * Scope keys MUST be treated as opaque strings by the orchestrator

                                       * The orchestrator MUST NOT parse business meaning from scope keys

                                       * The caller or schedule-expansion logic is responsible for constructing valid scope keys

Examples
                                          * tenant-wide run: ''

                                          * subtenant run: subtenant:ABC

                                          * portfolio run: portfolio:4711

v1 Derivation Rules
                                             * Scheduled run requests created from standard tenant schedule bindings default to ScopeKey = ''

                                             * Manual run requests may specify ScopeKey

                                             * If a manual run request omits ScopeKey, it defaults to ''

                                             * If future versions support schedule-driven multi-scope expansion, they must still persist explicit scope keys per BIN

0.8 ScopeKey vs ExecutionContext
ScopeKey and ExecutionContext are different concepts and MUST NOT be treated as interchangeable.
ScopeKey
ScopeKey is the orchestration identity for a run. It is used for:
                                                * uniqueness

                                                * dependency correlation

                                                * occurrence correlation

                                                * filtering and operational visibility

                                                * scope-sensitive dependency matching

ScopeKey is not a full runtime payload.
ExecutionContext
ExecutionContext is a structured runtime payload passed to the runner. It may contain:
                                                   * business date

                                                   * subtenant identifier

                                                   * portfolio identifier

                                                   * operator-entered parameters

                                                   * force intent

                                                   * other runner input

Mandatory Rules
                                                      * Orchestration decisions MUST use ScopeKey where the spec says scope matters

                                                      * Orchestration logic MUST NOT compare full ExecutionContextJson values to determine dependency satisfaction or uniqueness

                                                      * ExecutionContextJson MAY contain values that also influenced how ScopeKey was chosen, but the orchestrator does not infer scope from it

                                                      * Two runs may have the same ScopeKey and different ExecutionContextJson

                                                      * Two runs may have different ScopeKey values even if parts of the ExecutionContextJson overlap

0.9 Execution Guarantee Model
v1 provides:
                                                         * at-least-once run request processing

                                                         * best-effort exactly-once instance creation through unique constraints

                                                         * single active execution per BIN through lease enforcement

v1 does not guarantee true global exactly-once execution across all possible infrastructure failures.

1. Purpose
Replace Windows Task Scheduler–based batch execution with a centralized, multi-tenant, dependency-aware, schedule-driven batch framework.
The system MUST support:
                                                            * multi-tenant job execution

                                                            * many-to-many schedules per job and tenant

                                                            * dependency-based orchestration

                                                            * gates and validations

                                                            * concurrency control at multiple levels

                                                            * manual run requests

                                                            * GUI visibility into past and future jobs

                                                            * repeated runs of the same job for the same tenant using different ScopeKey values

The system MUST persist its orchestration state in Microsoft SQL Server and MUST target Microsoft SQL Server as the supported relational database platform for v1.

3. High-Level Architecture
3.1 Components
1. Batch.Api.Host
Responsibilities:
                                                               * CRUD jobs

                                                               * CRUD runner profiles

                                                               * CRUD batch schedules

                                                               * CRUD bindings

                                                               * CRUD tenant execution parameters

                                                               * manual run requests via HTTP

                                                               * query history and future schedule previews

                                                               * tenant-scoped access

                                                               * administrative access for authorized operators

Important rule:
                                                                  * The API never executes jobs directly

                                                                  * The API only creates or manages configuration and run requests

2. Batch.Orchestrator.Host
Responsibilities:
                                                                     * scheduler loop

                                                                     * request firing loop

                                                                     * instance evaluator loop

                                                                     * dispatcher / worker loop

                                                                     * all job execution

                                                                     * all dependency, gate, concurrency and mutex enforcement

                                                                     * process launch planning

Important rule:
                                                                        * The orchestrator is the only component allowed to execute jobs

3. Batch.Cli
Responsibilities:
                                                                           * manual run initiation from legacy applications

                                                                           * scripted/manual run initiation by operators

                                                                           * pre-flight tenant access validation

                                                                           * creation of run requests through shared application services

Important rule:
                                                                              * The CLI never executes jobs directly

                                                                              * The CLI never performs orchestration logic locally

                                                                              * The CLI only creates run requests

4. Runner Abstraction
public interface IJobRunner
{
   Task<RunResult> ExecuteAsync(RunContext context, CancellationToken ct);
}
v1 Runner Model
v1 runtime execution uses a single high-level runner type:
                                                                                 * Process

This means the orchestrator executes an external OS process and is responsible for:
                                                                                    * resolving executable path

                                                                                    * resolving working directory

                                                                                    * building command-line arguments

                                                                                    * injecting job-specific optional date argument behavior

                                                                                    * enforcing timeout

                                                                                    * capturing exit code

                                                                                    * capturing stdout/stderr references

                                                                                    * recording attempt outcome

Important Design Rule
VB and .NET are not orchestration runner types in v1.
They are represented as reusable runner profiles that share the same high-level Process runner implementation but differ in:
                                                                                       * executable path convention

                                                                                       * argument construction convention

                                                                                       * required tenant execution parameters

                                                                                       * optional default working directory behavior

Initial v1 Runner Support
The v1 runtime supports only:
                                                                                          * Process

Process Launch Profiles
A runner profile defines reusable launch behavior for a family of jobs, for example:
                                                                                             * legacy VB-style launch

                                                                                             * .NET batch-style launch

                                                                                             * batch file style launch

                                                                                             * PowerShell style launch

Examples:
                                                                                                * Legacy VB-style profile may render command arguments like:
<tenant execution parameter> <job name>

                                                                                                * .NET batch-style profile may render command arguments like:
-tenant:<tenantCode> -job:<jobName>

The orchestrator core remains unaware of business meaning such as “VB” or “.NET”; it only executes a Process job using a referenced runner profile.
3.2 Solution Structure
The solution SHOULD be split into separate projects with shared contracts/domain logic and separate executable hosts.
Recommended host split:
                                                                                                   * Batch.Api.Host

                                                                                                   * Batch.Orchestrator.Host

                                                                                                   * Batch.Cli

Recommended shared layers:
                                                                                                      * Contracts / Abstractions

                                                                                                      * Domain

                                                                                                      * Persistence

                                                                                                      * Application services

                                                                                                      * Orchestrator services

3.3 CLI Behavior (v1)
The CLI is intended as a legacy-friendly entry point.
CLI Flow
                                                                                                         * Resolve tenant code to configured tenant root path from TEN_TENANT.TEN_ROOT_PATH

                                                                                                         * Resolve the pre-flight marker file name from application configuration

                                                                                                         * Check that the marker file under the tenant root path is readable

                                                                                                         * If the file is not readable, abort immediately with non-zero exit code

                                                                                                         * If the file is readable, create a manual run request using shared application services

                                                                                                         * Let the orchestrator process the request normally

Important Constraints
                                                                                                            * The marker file check is a pre-flight environment/access check only

                                                                                                            * It is not a complete authorization model

                                                                                                            * The CLI may request force execution semantics, but force must never bypass mutex or concurrency enforcement

                                                                                                            * The CLI MUST NOT write directly to orchestration tables except through shared application services

3.4 Execution Invariant
All entry points create run requests only.
The following components may create run requests:
                                                                                                               * scheduler

                                                                                                               * API

                                                                                                               * CLI

Only the orchestrator may:
                                                                                                                  * create runnable state transitions

                                                                                                                  * evaluate dependencies

                                                                                                                  * evaluate gates

                                                                                                                  * enforce concurrency and mutex rules

                                                                                                                  * execute jobs

                                                                                                                  * persist execution attempts and outcomes

5. Database Model (Physical Schema Specification)
This section defines the complete physical database model for v1.
Implementation rules:
                                                                                                                                                                              * every table used by the backend must be defined here

                                                                                                                                                                              * every column must document type, nullability, valid values if applicable, and usage

                                                                                                                                                                              * any schema change must be reflected here before implementation

                                                                                                                                                                              * where a rule cannot be fully enforced in Microsoft SQL Server constraints, it MUST be enforced in application services

The database guarantees structural integrity.
Application services guarantee orchestration validity.
Microsoft SQL Server Requirement
v1 MUST support Microsoft SQL Server as the relational database platform.
Implementation assumptions for v1:
                                                                                                                                                                                 * string columns use nvarchar(...) or nvarchar(max)

                                                                                                                                                                                 * timestamps use datetime2(3)

                                                                                                                                                                                 * booleans use bit

                                                                                                                                                                                 * filtered unique indexes may be used where supported by Microsoft SQL Server

                                                                                                                                                                                 * EF Core mappings MUST target Microsoft SQL Server-compatible schema types and behaviors

Profile Mode Semantics
LegacyVbStyle
Used for legacy VB-style process launch contracts.
Default command shape:
<ExecutablePath> <RequiredTenantExecutionParameter> <JobName> [extra args] [optional date]
Typical example:
legacy.exe C:\defs\tst.def ImportTrades
This mode may require a tenant execution parameter such as legacyConfigPath.
DotNetBatchStyle
Used for .NET batch launcher contracts.
Default command shape:
<ExecutablePath> -tenant:<TenantCode> -job:<JobName> [extra args] [optional date]
Typical example:
batch.exe -tenant:TST -job:ImportTrades
BatchFileStyle
Used for .bat / .cmd launch behavior.
PowerShellStyle
Used for PowerShell script launch behavior.
CustomTemplate
Used when base process-launch arguments must be template-driven rather than mode-driven.

 No date argument is appended

                                                                                                                                                                                                   * Positional
 Date value is appended as a standalone positional argument

                                                                                                                                                                                                   * NamedValueSameToken
 Date rendered as one token, for example /date:20260308 or -date=2026-03-08

                                                                                                                                                                                                   * NamedSeparateToken
 Date rendered as two tokens, for example /date 20260308

The date value is formatted using BAJ_DATE_FORMAT after applying BAJ_DATE_OFFSET_DAYS.

6. Scheduling Model
6.1 Lookahead Strategy
Chosen approach:
                                                                                                                                                                                                                                                                           * scheduler interval: 30 seconds

                                                                                                                                                                                                                                                                           * lookahead window: 5 minutes

BRQ is created when:
                                                                                                                                                                                                                                                                              * NextFireUtc <= now + lookahead

Values:
                                                                                                                                                                                                                                                                                 * BRQ_FIRE_AT_UTC = scheduled slot time

                                                                                                                                                                                                                                                                                 * BRQ_STATUS = Planned

Instances are only created when:
                                                                                                                                                                                                                                                                                    * FireAtUtc <= now

6.2 Source of Truth for Scheduling
Schedule evaluation uses BSC_TIME_ZONE, not tenant time zone.
TEN_TIME_ZONE is metadata for UI and future use, not the primary scheduler clock for BSC.
A single schedule can therefore be shared across tenants in different tenant time zones without changing the schedule fire-time calculation.
6.3 DST Rules
Nonexistent Local Time
If configured local time does not exist due to DST forward jump:
                                                                                                                                                                                                                                                                                       * skip that occurrence

                                                                                                                                                                                                                                                                                       * compute next valid slot

Ambiguous Local Time
If configured local time occurs twice due to DST backward shift:
                                                                                                                                                                                                                                                                                          * run once only

                                                                                                                                                                                                                                                                                          * choose the first occurrence in UTC

6.4 Misfire Rules
Skip
If a schedule slot is missed and policy is Skip:
                                                                                                                                                                                                                                                                                             * do not create late BIN for missed slot

                                                                                                                                                                                                                                                                                             * scheduler advances to next future slot

                                                                                                                                                                                                                                                                                             * an event/log entry SHOULD record the skip

RunOnceNextWindow
If one or more schedule slots were missed while scheduler was down:
                                                                                                                                                                                                                                                                                                * create exactly one catch-up BRQ at scheduler recovery

                                                                                                                                                                                                                                                                                                * use the most recent missed slot as BRQ_SLOT_KEY

                                                                                                                                                                                                                                                                                                * BRQ_FIRE_AT_UTC = now

                                                                                                                                                                                                                                                                                                * then continue normal future schedule progression

v1 intentionally collapses multiple missed slots into one catch-up request.
6.5 Slot Key Format
Slot key for schedule-driven BRQ must be deterministic and timezone-safe.
Recommended canonical format:
yyyy-MM-ddTHH:mm:ss|<TimeZoneId>|<ScheduleType>|<LogicalLocalSlot>
Implementation may use a different canonical deterministic string only if it uniquely identifies the logical schedule occurrence and remains stable across restarts.
6.6 Supported Schedule Config Schemas (v1)
DailyAt
{
 "localTime": "06:00:00"
}
Required fields:
                                                                                                                                                                                                                                                                                                   * localTime as HH:mm:ss

WeeklyAt
{
 "daysOfWeek": ["Monday", "Tuesday", "Wednesday"],
 "localTime": "06:00:00"
}
Required fields:
                                                                                                                                                                                                                                                                                                      * daysOfWeek: non-empty array of weekday names

                                                                                                                                                                                                                                                                                                      * localTime: HH:mm:ss

RepeatInWindow
{
 "windowStart": "08:00:00",
 "windowEnd": "16:00:00",
 "intervalMinutes": 30
}
Required fields:
                                                                                                                                                                                                                                                                                                         * windowStart

                                                                                                                                                                                                                                                                                                         * windowEnd

                                                                                                                                                                                                                                                                                                         * intervalMinutes

Rules:
                                                                                                                                                                                                                                                                                                            * windowStart < windowEnd

                                                                                                                                                                                                                                                                                                            * intervalMinutes >= 1

LastBankDay
{
 "localTime": "06:00:00",
 "calendarCode": "NO"
}
Required fields:
                                                                                                                                                                                                                                                                                                               * localTime

                                                                                                                                                                                                                                                                                                               * calendarCode

MultipleTimesPerDay
{
 "times": ["06:00:00", "12:00:00", "18:00:00"]
}
Required fields:
                                                                                                                                                                                                                                                                                                                  * times: non-empty array of unique HH:mm:ss values

Any other JSON shape MUST be rejected by service validation.

7. Orchestrator Responsibilities and Flow
The orchestrator is implemented as one or more BackgroundService loops.
7.1 Scheduler (Batch Schedules → Run Requests)
Purpose
Materialize near-future schedule slots into run requests using a lookahead window.
Key Rules
                                                                                                                                                                                                                                                                                                                     * lookahead window: 5 minutes

                                                                                                                                                                                                                                                                                                                     * scheduler interval: 30 seconds

                                                                                                                                                                                                                                                                                                                     * requests created for schedule slots use the scheduled slot time, not now

                                                                                                                                                                                                                                                                                                                     * idempotent creation via unique key (BscId, SlotKey)

Inputs
                                                                                                                                                                                                                                                                                                                        * enabled BSC_BATCH_SCHEDULE rows

Outputs
                                                                                                                                                                                                                                                                                                                           * creates BRQ_BATCH_RUN_REQUEST rows with Status = Planned

Flow
For each enabled batch schedule:
                                                                                                                                                                                                                                                                                                                              * ensure BSC_NEXT_FIRE_UTC is set

                                                                                                                                                                                                                                                                                                                              * while BSC_NEXT_FIRE_UTC <= now + lookahead:

                                                                                                                                                                                                                                                                                                                                 * compute SlotKey for BSC_NEXT_FIRE_UTC

                                                                                                                                                                                                                                                                                                                                 * insert BRQ with:

                                                                                                                                                                                                                                                                                                                                    * TriggerType = Schedule

                                                                                                                                                                                                                                                                                                                                    * BscId = current schedule

                                                                                                                                                                                                                                                                                                                                    * SlotKey = computed slot key

                                                                                                                                                                                                                                                                                                                                    * FireAtUtc = BSC_NEXT_FIRE_UTC

                                                                                                                                                                                                                                                                                                                                    * Status = Planned

                                                                                                                                                                                                                                                                                                                                    * ScopeKey = ''

                                                                                                                                                                                                                                                                                                                                    * ForceGates = 0

                                                                                                                                                                                                                                                                                                                                       * advance BSC_NEXT_FIRE_UTC = ComputeNext(BSC_NEXT_FIRE_UTC) and persist

7.2 Request Firing (Run Requests → Job Instances)
Purpose
Turn due run requests into job instances for the tenants that are bound to the batch schedule or directly targeted by manual requests.
Inputs
                                                                                                                                                                                                                                                                                                                                          * BRQ_BATCH_RUN_REQUEST where Status = Planned and FireAtUtc <= now

                                                                                                                                                                                                                                                                                                                                          * TJS_TENANT_JOB_SCHEDULE bindings for BSC_ID for schedule-driven requests

Outputs
                                                                                                                                                                                                                                                                                                                                             * creates one BIN_BATCH_JOB_INSTANCE per applicable expansion item

                                                                                                                                                                                                                                                                                                                                             * marks BRQ as Fired

Flow for Schedule-Driven BRQ
For each due schedule-driven BRQ:
                                                                                                                                                                                                                                                                                                                                                * load all enabled bindings where:

                                                                                                                                                                                                                                                                                                                                                   * TJS_BSC_ID = BRQ_BSC_ID

                                                                                                                                                                                                                                                                                                                                                   * binding effective window matches

                                                                                                                                                                                                                                                                                                                                                      * for each binding create BIN:

                                                                                                                                                                                                                                                                                                                                                         * BIN_TEN_ID = TJS_TEN_ID

                                                                                                                                                                                                                                                                                                                                                         * BIN_BAJ_ID = TJS_BAJ_ID

                                                                                                                                                                                                                                                                                                                                                         * BIN_BSC_ID = BRQ_BSC_ID

                                                                                                                                                                                                                                                                                                                                                         * BIN_OCCURRENCE_KEY = BRQ_SLOT_KEY

                                                                                                                                                                                                                                                                                                                                                         * BIN_SCOPE_KEY = ''

                                                                                                                                                                                                                                                                                                                                                         * BIN_PLANNED_START_UTC = BRQ_FIRE_AT_UTC

                                                                                                                                                                                                                                                                                                                                                         * BIN_STATUS = Planned

                                                                                                                                                                                                                                                                                                                                                            * mark BRQ as Fired

Flow for Manual BRQ
A manual request may have:
                                                                                                                                                                                                                                                                                                                                                               * tenant id

                                                                                                                                                                                                                                                                                                                                                               * job id

                                                                                                                                                                                                                                                                                                                                                               * optional IncludePrereqs

                                                                                                                                                                                                                                                                                                                                                               * optional ScopeKey

                                                                                                                                                                                                                                                                                                                                                               * optional execution context

Manual request firing creates BIN instances for the requested tenant/job and, if requested, prerequisite jobs.
7.3 Manual Dependency Graph Expansion Rules
This section is mandatory and defines v1 behavior for IncludePrereqs = true.
Expansion Base
                                                                                                                                                                                                                                                                                                                                                                  * Expansion is performed at request-firing time

                                                                                                                                                                                                                                                                                                                                                                  * Expansion uses the dependency graph rooted at BRQ_BAJ_ID

                                                                                                                                                                                                                                                                                                                                                                  * Expansion includes the full transitive prerequisite graph

                                                                                                                                                                                                                                                                                                                                                                  * Expansion order MUST be topological

Node Identity
For expansion purposes, a node is uniquely identified by:
                                                                                                                                                                                                                                                                                                                                                                     * target tenant id

                                                                                                                                                                                                                                                                                                                                                                     * job id

                                                                                                                                                                                                                                                                                                                                                                     * occurrence key

                                                                                                                                                                                                                                                                                                                                                                     * scope key

The same logical node MUST only be created once.
If multiple dependency paths resolve to the same node identity, they collapse into one BIN.
Occurrence Key Rule
All BIN created from the same manual BRQ share the same occurrence key.
For manual requests:
                                                                                                                                                                                                                                                                                                                                                                        * BIN_OCCURRENCE_KEY = BRQ_ID as string

Scope Assignment Rule
Unless explicitly defined otherwise in a future version, all BIN created from one manual BRQ use the same ScopeKey as the originating request.
BAD_SCOPE_RULE = IgnoreScope affects dependency matching only.
It does not change the scope assigned to created prerequisite BIN.
Tenant Resolution Rule
SameTarget
Prerequisite BIN uses the same tenant as the dependent BIN.
SameTenantAnyScope
Prerequisite BIN uses the same tenant as the dependent BIN.
SpecificTenant
Prerequisite BIN uses BAD_TARGET_TEN_ID.
Global
Rejected in v1. No BIN may be expanded using Global.
Failure Rules
If dependency expansion encounters any of the following, the BRQ MUST become Failed and no partial BIN creation is allowed:
                                                                                                                                                                                                                                                                                                                                                                           * dependency cycle

                                                                                                                                                                                                                                                                                                                                                                           * unsupported Global selector

                                                                                                                                                                                                                                                                                                                                                                           * missing BAD_TARGET_TEN_ID for SpecificTenant

                                                                                                                                                                                                                                                                                                                                                                           * disabled tenant required for expansion

                                                                                                                                                                                                                                                                                                                                                                           * missing tenant-job configuration required for expansion

                                                                                                                                                                                                                                                                                                                                                                           * disabled tenant-job required for expansion

Result
For a valid IncludePrereqs = true request:
                                                                                                                                                                                                                                                                                                                                                                              * create one BIN per unique expanded node

                                                                                                                                                                                                                                                                                                                                                                              * all created BIN share:

                                                                                                                                                                                                                                                                                                                                                                                 * same occurrence key

                                                                                                                                                                                                                                                                                                                                                                                 * same BRQ

                                                                                                                                                                                                                                                                                                                                                                                 * same scope key

                                                                                                                                                                                                                                                                                                                                                                                    * the orchestrator then evaluates dependencies normally

7.4 Evaluator (Planned/Blocked → Ready)
Purpose
Decide when a job instance is runnable. Instances may be blocked by dependencies, gates, or concurrency.
Inputs
                                                                                                                                                                                                                                                                                                                                                                                       * BIN_BATCH_JOB_INSTANCE with Status = Planned or Blocked

Outputs
                                                                                                                                                                                                                                                                                                                                                                                          * updates BIN status to Ready, Blocked, or Failed

Evaluation Order
Stop on first non-passing condition:
                                                                                                                                                                                                                                                                                                                                                                                             * tenant active?

                                                                                                                                                                                                                                                                                                                                                                                             * tenant job enabled?

                                                                                                                                                                                                                                                                                                                                                                                             * dependencies satisfied?

                                                                                                                                                                                                                                                                                                                                                                                             * gates satisfied?

                                                                                                                                                                                                                                                                                                                                                                                             * concurrency available?

Deterministic Result Rules
                                                                                                                                                                                                                                                                                                                                                                                                * If all pass, set Status = Ready

                                                                                                                                                                                                                                                                                                                                                                                                * If tenant is disabled, set Status = Failed

                                                                                                                                                                                                                                                                                                                                                                                                * If tenant-job is disabled, set Status = Failed

                                                                                                                                                                                                                                                                                                                                                                                                * If blocked by dependencies, set Status = Blocked

                                                                                                                                                                                                                                                                                                                                                                                                * If blocked by gate with BlockUntilLatest, set Status = Blocked

                                                                                                                                                                                                                                                                                                                                                                                                * If gate fails with FailImmediately, set Status = Failed

                                                                                                                                                                                                                                                                                                                                                                                                * If blocked by concurrency, set Status = Blocked

Reevaluation Rules
Block reason category
	Result
	NextEvalUtc rule
	Dependency not yet satisfied
	Blocked
	now + RecheckInterval
	Gate unsatisfied with BlockUntilLatest
	Blocked
	now + RecheckInterval
	Concurrency unavailable
	Blocked
	now + RecheckInterval
	Tenant disabled
	Failed
	null
	Tenant-job disabled
	Failed
	null
	Missing prerequisite for schedule/manual without expanded prerequisite creation
	Blocked
	now + RecheckInterval
	RecheckInterval Rule
                                                                                                                                                                                                                                                                                                                                                                                                   * If BIN_BSC_ID != null and related schedule has BSC_RECHECK_EVERY_SEC, use that value

                                                                                                                                                                                                                                                                                                                                                                                                   * Otherwise use default v1 reevaluation interval: 30 seconds

Latest Start Rule
If the BIN originated from a schedule and the related schedule defines BSC_LATEST_START_LOCAL, then once the local schedule timezone passes the latest start cutoff for that occurrence:
                                                                                                                                                                                                                                                                                                                                                                                                      * a Blocked BIN MUST become Failed

                                                                                                                                                                                                                                                                                                                                                                                                      * BIN_BLOCK_REASON MUST explain that latest start time has passed

7.5 Dispatcher/Worker (Ready → Running → Terminal)
Purpose
Execute runnable instances safely across one or more workers.
Inputs
                                                                                                                                                                                                                                                                                                                                                                                                         * BIN_BATCH_JOB_INSTANCE with Status = Ready

                                                                                                                                                                                                                                                                                                                                                                                                         * referenced BAJ_BATCH_JOB

                                                                                                                                                                                                                                                                                                                                                                                                         * referenced RUN_RUNNER_PROFILE

                                                                                                                                                                                                                                                                                                                                                                                                         * referenced tenant data and tenant execution parameters where needed

Outputs
                                                                                                                                                                                                                                                                                                                                                                                                            * lease row

                                                                                                                                                                                                                                                                                                                                                                                                            * attempt record

                                                                                                                                                                                                                                                                                                                                                                                                            * final instance status

Flow
                                                                                                                                                                                                                                                                                                                                                                                                               1. Select ready instance ordered by:

                                                                                                                                                                                                                                                                                                                                                                                                                  * BIN_PLANNED_START_UTC

                                                                                                                                                                                                                                                                                                                                                                                                                  * tenant job priority descending where available

                                                                                                                                                                                                                                                                                                                                                                                                                  * BIN_CREATED_UTC

                                                                                                                                                                                                                                                                                                                                                                                                                     2. Acquire lease to prevent double execution

                                                                                                                                                                                                                                                                                                                                                                                                                     3. Re-check concurrency inside the same transaction that transitions Ready -> Running

                                                                                                                                                                                                                                                                                                                                                                                                                     4. Resolve process launch plan:

                                                                                                                                                                                                                                                                                                                                                                                                                        * load job

                                                                                                                                                                                                                                                                                                                                                                                                                        * load runner profile

                                                                                                                                                                                                                                                                                                                                                                                                                        * load tenant

                                                                                                                                                                                                                                                                                                                                                                                                                        * load required tenant execution parameters

                                                                                                                                                                                                                                                                                                                                                                                                                        * render executable path

                                                                                                                                                                                                                                                                                                                                                                                                                        * render working directory

                                                                                                                                                                                                                                                                                                                                                                                                                        * render base arguments from runner profile mode

                                                                                                                                                                                                                                                                                                                                                                                                                        * append job extra arguments if any

                                                                                                                                                                                                                                                                                                                                                                                                                        * append optional job date argument if configured

                                                                                                                                                                                                                                                                                                                                                                                                                           5. Mark BIN as Running and create a BAT attempt

                                                                                                                                                                                                                                                                                                                                                                                                                           6. Execute via Process runner

                                                                                                                                                                                                                                                                                                                                                                                                                           7. Run validations

                                                                                                                                                                                                                                                                                                                                                                                                                           8. Mark BIN as Succeeded or Failed and persist outputs

Important Rule
The dispatcher must build command-line arguments using:
                                                                                                                                                                                                                                                                                                                                                                                                                              * runner profile reusable behavior first

                                                                                                                                                                                                                                                                                                                                                                                                                              * job-specific overrides second

                                                                                                                                                                                                                                                                                                                                                                                                                              * job-specific optional date argument last

This allows the same runner profile to be reused by many jobs while preserving per-job date semantics.

8. Status Machines
8.1 BRQ Status Transitions
Allowed transitions:
                                                                                                                                                                                                                                                                                                                                                                                                                                 * Planned -> Fired

                                                                                                                                                                                                                                                                                                                                                                                                                                 * Planned -> Cancelled

                                                                                                                                                                                                                                                                                                                                                                                                                                 * Planned -> Failed

No other transitions allowed.
Meaning:
                                                                                                                                                                                                                                                                                                                                                                                                                                    * Planned: request exists and is not yet expanded into BIN

                                                                                                                                                                                                                                                                                                                                                                                                                                    * Fired: all BIN for this BRQ have been materialized

                                                                                                                                                                                                                                                                                                                                                                                                                                    * Cancelled: request was cancelled before firing

                                                                                                                                                                                                                                                                                                                                                                                                                                    * Failed: request could not be expanded due to unrecoverable orchestration error

Once Fired, Cancelled, or Failed, BRQ is terminal.
8.2 BIN Status Transitions
Allowed transitions:
                                                                                                                                                                                                                                                                                                                                                                                                                                       * Planned -> Blocked

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Planned -> Ready

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Planned -> Cancelled

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Planned -> Failed

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Blocked -> Ready

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Blocked -> Failed

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Blocked -> Cancelled

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Ready -> Running

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Ready -> Cancelled

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Running -> Succeeded

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Running -> Failed

                                                                                                                                                                                                                                                                                                                                                                                                                                       * Running -> Cancelled

No transitions out of terminal states:
                                                                                                                                                                                                                                                                                                                                                                                                                                          * Succeeded

                                                                                                                                                                                                                                                                                                                                                                                                                                          * Failed

                                                                                                                                                                                                                                                                                                                                                                                                                                          * Skipped

                                                                                                                                                                                                                                                                                                                                                                                                                                          * Cancelled

Meaning:
                                                                                                                                                                                                                                                                                                                                                                                                                                             * Planned: created but not yet evaluated

                                                                                                                                                                                                                                                                                                                                                                                                                                             * Blocked: not currently runnable

                                                                                                                                                                                                                                                                                                                                                                                                                                             * Ready: runnable and eligible for dispatch

                                                                                                                                                                                                                                                                                                                                                                                                                                             * Running: lease acquired and execution started

                                                                                                                                                                                                                                                                                                                                                                                                                                             * Succeeded: execution and required validations passed

                                                                                                                                                                                                                                                                                                                                                                                                                                             * Failed: execution failed or required validation failed

                                                                                                                                                                                                                                                                                                                                                                                                                                             * Skipped: reserved only, not produced in v1 runtime

                                                                                                                                                                                                                                                                                                                                                                                                                                             * Cancelled: intentionally cancelled before or during execution

9. Retry Rules
9.1 Retry Model
v1 supports:
                                                                                                                                                                                                                                                                                                                                                                                                                                                * manual retry only

                                                                                                                                                                                                                                                                                                                                                                                                                                                * no automatic retry policy

POST /instances/{binId}/retry must create a new BRQ rather than mutate a terminal BIN back to active state.
9.2 Retry Request Behavior
Retry of a failed or cancelled BIN creates a new manual BRQ with:
                                                                                                                                                                                                                                                                                                                                                                                                                                                   * same TEN_ID

                                                                                                                                                                                                                                                                                                                                                                                                                                                   * same BAJ_ID

                                                                                                                                                                                                                                                                                                                                                                                                                                                   * same SCOPE_KEY

                                                                                                                                                                                                                                                                                                                                                                                                                                                   * INCLUDE_PREREQS = 0

                                                                                                                                                                                                                                                                                                                                                                                                                                                   * same execution context unless caller explicitly overrides

                                                                                                                                                                                                                                                                                                                                                                                                                                                   * FIRE_AT_UTC = now

Retry does not reuse the original BIN.
9.3 Attempt Numbering
For a given BIN:
                                                                                                                                                                                                                                                                                                                                                                                                                                                      * first execution creates BAT_ATTEMPT_NO = 1

                                                                                                                                                                                                                                                                                                                                                                                                                                                      * if worker crashes before completion and BIN is safely re-dispatched, same BIN may create a later attempt

                                                                                                                                                                                                                                                                                                                                                                                                                                                      * BIN_ATTEMPT_NO equals latest attempt number for that BIN

Manual retry through API does not increment attempt number on old BIN; it creates a new BIN under a new BRQ.
________________


10. Cancellation Rules
10.1 BRQ Cancellation
POST /requests/{brqId}/cancel is only allowed when BRQ is Planned.
If allowed:
                                                                                                                                                                                                                                                                                                                                                                                                                                                         * BRQ becomes Cancelled

                                                                                                                                                                                                                                                                                                                                                                                                                                                         * no BIN are created from that BRQ

If BRQ is already Fired, cancellation MUST return validation error.
10.2 BIN Cancellation
v1 does not provide a direct BIN cancel endpoint.
Running BIN
If future cancellation of running jobs is needed, the worker may pass a CancellationToken, but v1 does not require process-kill semantics.
If host shutdown happens during running execution:
                                                                                                                                                                                                                                                                                                                                                                                                                                                            * worker should try graceful cancellation

                                                                                                                                                                                                                                                                                                                                                                                                                                                            * if process does not stop in grace period, mark BIN failed on recovery if lease expires and execution outcome is unknown

11. Dependency Model
Dependencies are evaluated against a target selector and a scope-matching rule.
11.1 Correlation Base
Dependency matching is always evaluated inside the same logical occurrence.
                                                                                                                                                                                                                                                                                                                                                                                                                                                               * scheduled runs correlate by OccurrenceKey

                                                                                                                                                                                                                                                                                                                                                                                                                                                               * manual runs correlate by BRQ-group occurrence key

A prerequisite from another occurrence must never satisfy a dependency.
11.2 Supported Dependency Target Selectors
SameTarget
Match prerequisite BIN where:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * same tenant

                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * same occurrence key

                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * same dependency target job

                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * then apply scope rule

SameTenantAnyScope
Match prerequisite BIN where:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * same tenant

                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * same occurrence key

                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * same dependency target job

                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * scope ignored regardless of current scope

SpecificTenant
Match prerequisite BIN where:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                        * tenant = BAD_TARGET_TEN_ID

                                                                                                                                                                                                                                                                                                                                                                                                                                                                        * same occurrence key

                                                                                                                                                                                                                                                                                                                                                                                                                                                                        * same dependency target job

                                                                                                                                                                                                                                                                                                                                                                                                                                                                        * then apply scope rule

Global
Reserved in schema, but not supported in v1 executable behavior.
Global dependencies MUST be rejected by service validation.
11.3 Supported Scope Rules
RequireSameScope
Prerequisite must have identical ScopeKey.
IgnoreScope
Prerequisite scope is ignored.
11.4 Dependency Satisfaction Mapping
Started
Satisfied if prerequisite BIN status is one of:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                           * Running

                                                                                                                                                                                                                                                                                                                                                                                                                                                                           * Succeeded

                                                                                                                                                                                                                                                                                                                                                                                                                                                                           * Failed

                                                                                                                                                                                                                                                                                                                                                                                                                                                                           * Cancelled

Succeeded
Satisfied only if prerequisite BIN status is:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * Succeeded

Completed
Satisfied if prerequisite BIN status is one of:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * Succeeded

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * Failed

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * Cancelled

11.5 Missing Prerequisite Behavior
If no candidate prerequisite BIN exists for a dependency:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * if current BIN came from manual request with IncludePrereqs = true, this is an orchestration error and the originating BRQ should already have failed during expansion

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * otherwise BIN remains Blocked

11.6 Dependency Cycles
The dependency definition graph must be acyclic.
The system must reject:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * self-dependency

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * direct cycle

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * indirect cycle

12. Gate Model
Gates are pre-execution checks evaluated after dependencies and before readiness.
12.1 Evaluation Order
Gates are evaluated in ascending BAG_ORDER.
Evaluation stops on first failing gate.
12.2 Fail Behavior
BlockUntilLatest
If the gate is not satisfied:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          * BIN becomes Blocked

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          * BIN may be re-evaluated later

FailImmediately
If the gate is not satisfied:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             * BIN becomes Failed

12.3 Supported Gate Types in v1
Executable in v1:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                * FileExists

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                * SqlExists

Persistable but not executable in v1:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   * SqlScalar

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   * Custom

If a non-executable gate type is configured for a job in v1, service validation MUST reject activation of that gate.
12.4 Supported Gate Config Schemas
FileExists
{
 "pathTemplate": "\\\\server\\share\\{tenantCode}\\input\\ready.txt",
 "mustExist": true
}
Required fields:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      * pathTemplate

13. Validation Model
Validations are post-execution checks evaluated after an attempt completes.
13.1 Evaluation Order
Validations are evaluated in ascending BAV_ORDER.
13.2 Final Status Rule
If any enabled validation with BAV_FAILS_JOB = 1 returns Fail, the BIN becomes Failed.
Warnings do not fail the BIN.
13.3 Supported Validation Types in v1
Executable in v1:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           * ExitCode

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           * FileExists

Persistable but not executable in v1:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * SqlExists

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * SqlScalar

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * Custom

If a non-executable validation type is configured for a job in v1, service validation MUST reject activation of that validation.
13.4 Supported Validation Config Schemas
ExitCode
{
 "allowedExitCodes": [0]
}
Required fields:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * allowedExitCodes: non-empty integer array

Validation passes if runner exit code is in the allowed set.
FileExists
Same schema as the FileExists gate, but evaluated after execution.
Process Launch Rules
Runner profile selection affects only process launch construction.
It does not affect:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * dependency evaluation

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * scope matching

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * concurrency counting

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * retry semantics

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * lease semantics

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * validation result semantics

14. Concurrency Model
Concurrency counts only BIN where BIN_STATUS = Running.
14.1 Check Order
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * tenant max parallel

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * tenant mutex group

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * job max global

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * job max per tenant

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * schedule max parallel group

The first failed check blocks the BIN and sets a matching block reason.
14.2 Tenant Max Parallel
If TCL_MAX_PARALLEL = N, tenant may have at most N running BIN across all jobs and scopes.
14.3 Tenant Mutex Group
BAJ_MUTEX_GROUP means:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          * inside the same tenant

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          * jobs sharing the same non-null mutex group

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          * may not run in parallel

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          * scope does not matter

Mutex is tenant-wide across scopes.
14.4 Job Max Global
BAJ_MAX_PARALLEL_GLOBAL counts all running BIN for the same BAJ_ID across all tenants and scopes.
14.5 Job Max Per Tenant
BAJ_MAX_PARALLEL_PER_TENANT counts all running BIN for the same BAJ_ID inside the same tenant across all scopes.
14.6 Schedule Max Parallel Group
BSC_MAX_PARALLEL_GROUP counts running BIN where:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             * same BSC_ID

It does not require same slot key.
14.7 Admission Race Protection
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                * evaluator may set BIN to Ready

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                * dispatcher must re-check concurrency inside the same transaction where it acquires lease and transitions Ready -> Running

The dispatcher is the final admission gate.
________________


15. Lease and Worker Recovery Rules
15.1 Lease Acquisition
A worker may only start a BIN if:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   * BIN is Ready

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   * no non-expired lease exists for that BIN

A unique constraint on BLE_BIN_ID must enforce single active lease row.
15.2 Lease Heartbeat
Worker must heartbeat lease while running.
Recommended default:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      * heartbeat every 15 seconds

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      * lease duration 60 seconds

15.3 Expired Lease Recovery
If lease expires and BIN is still Running:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         * another worker may mark the BIN recoverable

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         * a new attempt may be started for the same BIN

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         * previous execution is treated as lost or unknown

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         * an event row must be written

This is one reason v1 is at-least-once, not true exactly-once.
________________


16. Manual Run Semantics
16.1 Single Job Run
A manual run request must specify:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            * tenant

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            * job

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            * optional scope key

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            * optional execution context

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            * optional include prerequisites flag

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            * optional force-gates flag

If scope key omitted, default ''.
16.2 IncludePrereqs Behavior
If IncludePrereqs = true:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               * expand transitive prerequisite graph

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               * create one BIN per unique dependency node required for the requested target job

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               * all created BIN share:

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * same occurrence key

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * same scope key

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * same BRQ

16.3 Disabled Jobs and Tenants
Manual requests must still respect:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * tenant active status

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * tenant-job enabled status

v1 behavior:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        * such manual requests MUST be rejected in application service validation

17. Force Execution Semantics
v1 supports a narrow force model.
17.1 Meaning
Force means:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           * gate evaluation may be bypassed

17.2 Force Does Not Bypass
Force must not bypass:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * tenant disabled

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * tenant-job disabled

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * dependency cycle validation

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * dependency evaluation

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * concurrency limits

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * mutex rules

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * lease rules

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * required runner configuration

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * required tenant execution parameters

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * executable path resolution

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * command-line validity

17.3 Persistence
Force intent MUST be stored explicitly as:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * BRQ_FORCE_GATES

It MUST NOT rely only on free-form execution context.
17.4 Applicability
Force is allowed only for manual/API-created requests.
Force is not allowed for schedule-created requests.

20. Example Scenarios and End-to-End Flow
Scenario A: Daily job for many tenants
Setup
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               * Job ImportTrades exists

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               * Schedule Morning A = DailyAt 06:00

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               * Tenants 1..45 bound to Morning A

Flow
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * Scheduler creates BRQ for slot 06:00

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * At 06:00, request firing expands BRQ into BIN instances for tenants 1..45

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * Evaluator blocks or unblocks each tenant instance based on gates, dependencies and concurrency

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  * Dispatcher executes ready instances under concurrency limits

Scenario B: Two groups run in parallel
Setup
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * Same job ImportTrades

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * Profile Morning A bound to tenants 1..45

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * Profile Morning B bound to tenants 46..90

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     * BSC_MAX_PARALLEL_GROUP = 2 for each profile

Flow
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        * Two BRQ are created, one per profile and slot

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        * Two sets of BIN instances are created

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        * Concurrency is enforced per schedule profile so each group runs two tenants at a time and both groups can run in parallel

Scenario C: Job runs multiple times per day
Setup
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           * Profile MarketHours = RepeatInWindow 08:00–16:00 every 30 minutes

Flow
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * Scheduler creates BRQ for each slot within lookahead

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              * Each BRQ fires at its slot time and creates BIN instances for subscribed tenants

Scenario D: Dependency “Job B after Job A started”
Setup
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * Dependency: B depends on A (Started)

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * Both jobs use the same occurrence key

Flow
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * BIN(A) becomes Running

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * Evaluator sees BIN(B) dependency satisfied once A has started

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * BIN(B) becomes Ready and can run subject to concurrency and mutex

Scenario E: Manual run now plus prerequisites
Setup
User requests manual run for tenant 42: Run ImportTrades now with IncludePrereqs = true
Flow
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * API creates BRQ with TriggerType = Manual, FireAtUtc = now

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * Request firing expands dependency graph and creates BIN for requested job and prerequisites

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * Evaluator resolves dependencies using shared occurrence key and scope key

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       * Dispatcher executes as capacity allows

Scenario F: Same tenant, same job, different scopes
Setup
Tenant 42 has job ImportTrades.
Manual requests:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          * tenant 42, job ImportTrades, scope subtenant:AAA

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          * tenant 42, job ImportTrades, scope subtenant:BBB

Flow
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             * these create separate BIN instances because ScopeKey differs

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             * dependency matching with RequireSameScope means subtenant:AAA only matches prerequisites for subtenant:AAA

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             * job max per tenant still counts both because job-per-tenant cap ignores scope

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             * mutex group also ignores scope

This is the intended v1 behavior.

Mandatory guidance:
                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * do not invent runtime behavior not defined in this document

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * reject unsupported v1 configurations in service validation

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * use enums as strings in both persistence and API JSON

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * treat ScopeKey as orchestration identity, not as a generic payload

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * do not use ExecutionContextJson for uniqueness or dependency matching

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * do not mutate terminal BIN back to active states

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * do not execute jobs outside the orchestrator

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * do not model VB and .NET as separate orchestration runner types

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * implement one high-level Process runner in v1

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * store tenant-specific launcher inputs in TEP_TENANT_EXECUTION_PARAMETER

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * keep date argument behavior on BAJ_BATCH_JOB

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * resolve runner profile behavior first, then append job-specific overrides and date argument

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * do not add runner-specific columns to TEN_TENANT unless they are universally meaningful

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 * target Microsoft SQL Server-compatible schema and behavior in EF Core configuration

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * Do we need persistent worker heartbeat monitoring beyond lease heartbeat?

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * Should CLI later switch to API-based request creation instead of shared-service usage?

                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    * Should future versions support secret or encrypted tenant execution parameters?
